# Conversión offline del perfil de lectura compartida

Ejecutar `andeiva-preview grouped-profile` únicamente como instalador root, después de un `grouped-inspect` autorizado reciente y un `grouped-prepare` correcto, con la API y el socket anteriores detenidos. El paquete debe provisionar el grupo exclusivo `andeiva-config-reader` y su registro versionado propiedad de root. Reanudar la API modifica su fingerprint: archivar el borrador obsoleto conocido y preparar de nuevo; nunca modificarlo automáticamente.

El conversor conserva el bloqueo real del checkpoint y los tres bloqueos de manifiestos de reservas. Sólo cambia `grouped/state`, `grouped/admission`, `grouped/plan` y `grouped/emergency`: mantiene el UID de API, asigna el grupo lector, establece directorios 02750 y archivos 0640, excepto el bloqueo de checkpoint que conserva 0600. Rechaza enlaces simbólicos, ACL, enlaces duros, alias, archivos pendientes, nombres inesperados, propietarios incorrectos y cambios de bytes o identidad de directorio. Calcula los hashes mediante descriptores retenidos antes y después de cambiar permisos.

Crea exclusivamente `/etc/andeiva-preview/grouped-profile.json`, accesible sólo por root. La versión 1 contiene `plan_sha256`, `prepared_sha256` y cuatro pines `access`, en orden state/admission/plan/emergency. Obtener `profiles`, `write_budget` y `local_origin` del `grouped-prepared.json` con ese SHA exacto. El resultado no activa servicios ni demuestra integridad o disponibilidad: el helper real sin capacidades adicionales debe validar independientemente la historia seleccionada y las reservas antes de Boot y de verificar el kernel.

Una conversión interrumpida no se repara automáticamente y se rechaza al reintentar. Conservar el destino parcial, los originales y los respaldos para recuperación controlada. No modifica diarios de origen, cuentas originales, sello de arranque local, interfaces ni políticas activas.

Prueba focal: `go test -race ./internal/previewruntime -run '^TestRoutedMigrationProfileV3' -count=1`. Calificación nativa root con binario de pruebas: `-test.run '^TestRoutedMigrationProfileFaultsNativeV3$' -andeiva-native-migration-profile-faults-v3` usa archivos temporales y fallos inyectados. `TestRoutedMigrationProfileNativeV3` con `-andeiva-native-migration-profile-v3` convierte el destino real preparado y requiere las condiciones offline anteriores. Los opt-in y los tests omitidos no constituyen evidencia de ejecución. G1 del helper y activación siguen siendo controles separados.

El grupo lector tampoco puede tener miembros primarios. Antes de convertir y publicar se exige enumeración acotada mediante getent passwd fijo. Los proveedores NSS passwd/group se limitan a files/systemd; se rechazan proveedores remotos o desconocidos porque su enumeración puede ser incompleta. No se cambia NSS.

### Continuidad privada de credenciales

Tras una preparación fría reciente y la conversión del perfil compartido, `andeiva-preview grouped-accounts` crea el archivo inactivo `grouped/accounts.json`. Conserva cada usuario, rol y digest de credencial original; añade solamente la identidad de sujeto y revisión de credencial del plan inspeccionado exacto. El archivo original permanece intacto. El nuevo pertenece a root, modo0440, legible por el grupo de la API y excluido del grupo lector de configuración. El arranque agrupado utiliza exclusivamente este archivo: su ausencia o invalidez no habilita credenciales heredadas. Un recibo operativo root-only registra hashes y el actor de proceso local-root, nunca credenciales. El comando no activa el runtime ni atribuye auditoría histórica. Antes del despliegue faltan las pruebas reales de acceso entre identidades y autenticación.


Ejecuta la prueba explícita de acceso con `bash packaging/preview/tests/grouped-accounts-native.sh --isolated-accounts-lab TEST_BINARY`, tras compilar `go test -c ./internal/previewruntime`. Monta un tmpfs pequeño y privado sobre el directorio de credenciales dentro de un nuevo namespace de montaje; lo restaura al salir. Las credenciales aleatorias sólo se transfieren por el pipe heredado del hijo API. Comprueba el loader real, autenticación admin/viewer, denegación al helper/grupo lector y rechazo cuando sólo existen credenciales heredadas. No convierte una migración instalada ni acredita RBAC HTTP. CI rechaza este modo privilegiado.
