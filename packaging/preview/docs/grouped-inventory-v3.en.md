# Helper network inventory

The grouped appliance factories explicitly negotiate `routed_inventory.v1` as the fifth IPC3 feature, after the three original features and `routed_integrity_gate.v1`. Profiles with three or four features remain available to their existing trusted factories. The production API requires all five and refuses an older helper before opening the writer; it never falls back to discovery in the API host namespace.

The `inventory` request has an empty object payload. It cannot select a namespace, interface, path or command. The helper provider checks its process and executing-thread namespace against trusted gateway metadata before and after `networkinventory.Discover`. Discovery performs two complete observations and refuses detectable changes. Its standard library OS calls are not individually context-cancellable. No policy, link, address, route, timer or listener is created by inventory.

Explicit typed response fields and nested required keys are checked on both sides. IPv4 and IPv6 host addresses, nullable masks and separate zones are preserved internally. Invalid, missing, null scalar, duplicate or oversized observations fail as a whole; they are not replaced by cached values, empty success or host data. The conservative escaped-JSON budget is 256 KiB, with existing interface/address-count bounds. Larger appliances may receive an unavailable result rather than a partial inventory.

The capless API receives inventory only through the authenticated inherited helper channel, with the existing run, namespace and monotonic sequence binding and three-second request deadline. It passes that provider to the existing authenticated `/api/v2/network/interfaces` endpoint. Existing RBAC and explicit public DTO filtering remain: internal ifindex, point-to-point/multicast flags and zones do not become extra public diagnostic fields. Management TLS and SO_NETNS_COOKIE validation remain on the host namespace.

Inventory does not qualify integrity, renew a lease or make the appliance Ready. Failure does not delete the last good ruleset. Tests cover typed round trips, bounds, no-argument dispatch, negotiation and downgrade refusal, fresh reads, provider errors and rejection of API-host discovery. The transport fixtures are in-process modeled observations; deployed gateway discovery and the full installation path require separate native evidence.
