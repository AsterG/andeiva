# Offline migration preparation

Keep the old helper and namespace manager alive, and stop the legacy API and socket for the whole cold window. `andeiva-preview grouped-inspect` creates an immutable root-only draft. Resuming the old API appends history and makes that fingerprint stale. Back up and explicitly retire only the known stale draft before a fresh inspection; the commands never refresh, replace or repair it automatically.

The authorized installer creates `/etc/andeiva-preview/grouped-migration-authorization.json` as root:root 0600 with O_EXCL. Its strict JSON is `{"version":1,"plan_sha256":"<exact draft digest>","bindings":[{"source":"<FW source>","actor":"<explicit historical actor>","subject":"<explicit new durable subject>","receipt_index":"<exact FW receipt index>"}]}`. Bindings are grants of replay continuity, not proof of historical human identity. Never infer them from usernames or credentials. The accounts file remains unchanged.

Run `andeiva-preview grouped-prepare` as the root installer without resuming the API between inspection, authorization and preparation. It repeats the capless inspection before provisioning. A capability-free APIUID worker opens the original FW and newly provisioned private directories under `/var/lib/andeiva-preview/grouped`: `local-origin`, `state`, `admission`, `plan`, `emergency`. Existing or partial directories cause refusal and are retained for authorized recovery. No old journal or boot directory is changed or relabeled.

The worker retains the FW lock while four bounded callbacks perform actual source-policy and inactive-domain absence readback. The new local domain receives exactly one initialize record with the actual timestamp. Both source locks and the destination lock are held during the fifth callback and selected migration publication. A fixed root parent performs each state/kernel/state observation against the old pinned namespace; the worker has no privilege or arbitrary command path. Pipe frames are bounded to 64 KiB, sequence- and request-digest-bound, with at most five verification requests. The 180-second preparation limit is offline process supervision, not a changed three-second runtime effect deadline.

The protected `/etc/andeiva-preview/grouped-prepared.json` output is O_EXCL and synchronized. It contains the exact draft hash, new-local provenance, three pool descriptors and explicit write budget of 1 GiB/32768 inodes. Pools have 18 slots and admission/plan/emergency capacities 4096/16384/8192 bytes. The new roots remain private API-owned 0700/0600. This record is **not activation**: shared-profile conversion, backed-up account identity persistence, independent helper full-history verification, a fresh namespace Boot/readback and sticky cutover are required before service exposure. Lost ACK or partial preparation is preserved, never retried by replacing directories.

Automated unit tests use real journal files and explicitly modeled readback; they check retained locks, two-rule FW preservation, exact local provenance and failures at each callback. `TestRoutedMigrationPrepareNativeV3` requires explicit `-andeiva-native-migration-prepare-v3`, a root-owned trusted test binary, a fresh authorized cold window and empty destination paths. It creates prepared storage and does not activate the runtime. Do not count its default skip as evidence.
